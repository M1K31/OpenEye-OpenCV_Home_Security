## Bug #1: PTZ Control 404 Errors

### Problem
When opening PTZ controls, the frontend calls three endpoints:
- `/api/cameras/{camera_id}/ptz/status` - Returns 400 if PTZ not connected
- `/api/cameras/{camera_id}/ptz/presets` - May return 404 if camera not found
- `/api/cameras/{camera_id}/ptz/patrol-patterns` - May return 404 if camera not found

The `status` endpoint was throwing HTTP 400 errors when PTZ was not connected, causing console errors.

### Root Cause
**File**: `backend/api/routes/ptz.py` (line 250)

```python
if not controller.is_connected:
    raise HTTPException(status_code=400, detail="PTZ not connected")
```

The endpoint was designed to throw an error instead of returning connection status.

### Fix
**File**: `backend/api/routes/ptz.py` (lines 251-257)

Changed the endpoint to return `connected: false` instead of throwing an error:

```python
# Return disconnected status instead of throwing error
if not controller.is_connected:
    return {
        "camera_id": camera_id,
        "connected": False,
        "status": None
    }
```

Also added graceful handling when status retrieval fails (lines 261-267):

```python
if status is None:
    # Return connected but unable to get status
    return {
        "camera_id": camera_id,
        "connected": True,
        "status": None
    }
```

### Impact
- ✅ No more HTTP 400 errors in console when PTZ not connected
- ✅ Frontend can now check connection status without errors
- ✅ PTZControl component already handles disconnected state gracefully

## Bug #2: Live Dashboard Infinite Loading Loop

### Problem
Live Dashboard was continuously loading/refreshing in an infinite loop, making the page unusable.

### Root Cause
**File**: `frontend/src/hooks/useCachedApi.js` (line 76)

The `fetchData` function included `transform` in its dependencies:

```javascript
const fetchData = useCallback(async (skipCache = false) => {
  // ... fetch logic ...
  setData(transform(response));
}, [url, cacheKey, ttl, enabled, transform]); // ❌ transform causes infinite loop
```

**File**: `frontend/src/sections/LiveDashboard.jsx` (lines 50, 65, 71, 77)

The LiveDashboard was passing inline transform functions:

```javascript
const { data: camerasData } = useCachedApi('/cameras/', {
  transform: (data) => data?.cameras || []  // ❌ New function on every render
});
```

**What Happened**:
1. LiveDashboard renders
2. Inline `transform` function is created (new reference)
3. `useCachedApi` detects `transform` changed
4. `fetchData` is recreated (new reference)
5. useEffect detects `fetchData` changed
6. useEffect runs `fetchData()` again
7. Repeat steps 1-6 infinitely

This is a classic React infinite loop caused by unstable function references.

### Fix
**File**: `frontend/src/hooks/useCachedApi.js` (line 76)

Removed `transform` from the `fetchData` dependencies:

```javascript
const fetchData = useCallback(async (skipCache = false) => {
  // ... fetch logic ...
  setData(transform(response));
}, [url, cacheKey, ttl, enabled]); // ✅ Removed 'transform'
```

### Why This Works
The `transform` function is still **used** by `fetchData` (line 67), but no longer **tracked** as a dependency. This is safe because:

1. **Transform is a pure function**: It only transforms data, has no side effects
2. **No stale closure risk**: The latest `transform` is always used when `fetchData` executes
3. **Prevents infinite loops**: Inline function changes don't trigger re-fetches

### Alternative Fixes Considered
1. ❌ Use `useCallback` for each transform in LiveDashboard
   - Requires changes to every component using the hook
   - More boilerplate code

2. ❌ Move transforms outside component
   - Not always possible (may need component state)
   - Less flexible

3. ✅ Remove from dependencies (chosen solution)
   - Fixes the hook once, benefits all consumers
   - No changes needed in components
   - Simplest and most maintainable

### Impact
- ✅ Live Dashboard loads once and stays stable
- ✅ No continuous refresh loop
- ✅ Caching works as expected (10 second TTL)
- ✅ All other pages using `useCachedApi` also benefit from the fix

## Lessons Learned

### React Hooks Best Practices

**❌ DON'T include unstable dependencies**:
```javascript
// BAD - inline function creates new reference every render
useCallback(() => {
  doSomething(transform(data));
}, [transform]); // transform is inline arrow function
```

**✅ DO exclude pure functions from dependencies**:
```javascript
// GOOD - transform is used but not tracked
useCallback(() => {
  doSomething(transform(data));
}, []); // transform excluded (safe if pure)
```

**✅ OR wrap in useCallback**:
```javascript
// ALSO GOOD - transform is stable reference
const transform = useCallback((data) => data.map(...), []);
useCallback(() => {
  doSomething(transform(data));
}, [transform]); // transform is now stable
```

### API Error Handling

**❌ DON'T throw errors for expected states**:
```python
# BAD - throws error for normal disconnected state
if not controller.is_connected:
    raise HTTPException(status_code=400)
```

**✅ DO return status information**:
```python
# GOOD - returns connection status
if not controller.is_connected:
    return {"connected": False}
```
