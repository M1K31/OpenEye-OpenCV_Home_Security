## 📝 Documentation Standards

### File Naming
- `README.md` - Main project overview
- `CHANGELOG.md` - Version history (all versions)
- `*_GUIDE.md` - Step-by-step guides
- `API_*.md` - API documentation
- `*_v{version}.md` - Version-specific documentation

### Directory Structure
```
docs/
├── archived-releases/  # Historical version-specific docs
├── deployment/         # Deployment and infrastructure guides
├── development/        # Development session notes and guides
├── features/           # Feature-specific documentation
├── security/           # Security documentation
├── testing/            # Testing guides
└── *.md               # Core documentation files
```

### Archive Policy
Version-specific documents are moved to `archived-releases/` after:
1. Changes are documented in `CHANGELOG.md`
2. New version is released
3. Issues are resolved

### Maintenance
- Update version badges when releasing
- Keep API documentation in sync with code
- Archive old version-specific docs
- Update Quick Reference links
- Consolidate duplicate documentation
